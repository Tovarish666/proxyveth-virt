# ProxyVeth v3.4 — развязка виртуального и реального номера

Один файл, `proxyveth.py`. Форк [ProxyControlService](https://github.com/Tovarish666/ProxyControlService)
v3.3, собираемый из апстрима скриптом — чтобы правки переносились на новые
версии, а не расходились с ними навсегда.

## Задача

mp.space строит адрес управления жёстко: увидел модем на `192.168.N.100` —
пошёл на `192.168.N.1`. Значит `N` обязан быть уникальным в пределах ВМ.

Но `N` — это номер модема на **своём** мини-сервере, и при сведении нескольких
мини-серверов в одну ВМ номера пересекаются: 1–10 на одном, 1–10 на другом,
101–115 на третьем. Свести их иначе нельзя.

v3.4 разделяет одно число на два:

| | что это | уникальность |
|---|---|---|
| `n` | номер, под которым модем видит mp.space | обязана быть на ВМ |
| `real` | октет модема на его мини-сервере | только на своём сервере |

Модем физически на `192.168.101.1`, mp.space видит его как `192.168.64.100` и
стучится на `192.168.64.1` — и получает ответ именно этого модема. Номера
назначаются произвольно и с настоящими никак не связаны.

## Таблица

```
n     | real | proxy
64    | 101  | 192.168.1.254:15000:modem101:te5xg83ted
246   | 102  | 192.168.1.254:15002:modem102:v4yeyzh43n
```

`real` принимает `101`, `192.168.101.100` и `192.168.101.1` — берётся третий
октет, чтобы колонку можно было заполнять копипастой откуда угодно.
Синонимы названия колонки: `modem`, `modem_n`, `modem_ip`, `mgmt`, `real_n`.

**Колонки `real` нет → `real = n` → поведение v3.3, ни одного лишнего правила.**
Старые таблицы работают без изменений.

Раздельные колонки (`proxy_host`, `proxy_port`, `login`, `password`) тоже
поддерживаются, как и раньше.

> `n` — это колонка, а не позиция строки. Сгенерировать его порядковым номером
> значит получить ту же историю, что с портами: вставка в середину сдвинет всю
> раскладку, и mp.space придётся переучивать.

## Что внутри, кроме развязки

**Посредник Host.** Одного NAT мало. Прошивка E3372 сверяет заголовок `Host` и
на чужой отвечает `307 Temporary Redirect`, не отдавая сессию. Замерено на
живом модеме — один пакет, одна разница:

| запрос | Host | ответ |
|---|---|---|
| `192.168.64.1` | `192.168.64.1` | **307** |
| `192.168.64.1` | `192.168.101.1` | **200 OK** |

Переписать заголовок на уровне пакетов нельзя — это содержимое потока. Поэтому
виртуальный адрес занимает посредник внутри namespace: правит `Host` в запросе
и адрес в `Location` ответа (на `GET /` модем отвечает
`Location: http://192.168.101.1/...` и увёл бы браузер на реальный адрес).
Правил DNAT при этом не ставится — `PREROUTING` перехватил бы пакет раньше
локальной доставки.

Запускается сам из `ns_up`, снимается в `ns_down`, виден в `check` и `status`.
Отдельных скриптов и демонов нет.

**Безопасные номера таблиц маршрутизации.** При `RT_TABLE_BASE=100` модемы
153/154/155 попадают в таблицы 253/254/255 — `default`, `main`, `local`.
`ns_down` на таком модеме выполняет `ip route flush table main`, и хост теряет
сеть вместе с SSH. Пока `N_MAX` был 200, это ждало своего часа; с развязкой
номера доходят до 254. `rt_table()` уводит такие номера в свой диапазон.

**`N_MAX` поднят с 200 до 254** — весь диапазон третьего октета.

## Установка

Репозиторий приватный, поэтому `wget` по raw-ссылке без токена не сработает.
Проще всего через `gh` на машине, где вы авторизованы:

```bash
gh repo clone Tovarish666/proxyveth-virt && install -m755 proxyveth-virt/proxyveth.py /usr/local/bin/proxyveth.py
```

```bash
ln -sf /usr/local/bin/proxyveth.py /usr/local/bin/proxyveth
```

Если репозиторий откроют, вернётся обычный однострочник:

```bash
wget -O /usr/local/bin/proxyveth.py https://raw.githubusercontent.com/Tovarish666/proxyveth-virt/main/proxyveth.py
```

Дальше как в v3.3: `proxyveth install`, `proxyveth sync`, `proxyveth up all`.

### Две настройки в `/etc/proxyveth/env`, выясненные на живом парке

```
RT_TABLE_BASE=1000
VETH_PREFIX=mdm
```

`RT_TABLE_BASE=1000` — второй рубеж защиты поверх `rt_table()`: при базе 1000
в системные таблицы не попасть в принципе.

`VETH_PREFIX=mdm` — **обязательно, если на той же ВМ работает mp.space.** Он
сбрасывает IPv4 на интерфейсах `eth*`, которых нет в его конфиге. Адрес
исчезает, следом ядро выбрасывает default из таблицы, и sing-box пишет
`no route to host` на адрес SOCKS5. Снаружи выглядит как «модем то отвечает,
то нет», и ищется это долго.

## Проверено

На ВМ `Msk1-2` (Ubuntu 24.04.4), два живых модема за прокси:

```
virt  real  SerialNumber           выход в сеть
64    101   9GVDW17215000571       178.176.72.38     v
246   102   9GVDW17516001299       128.71.101.119    v

модем 101: 1 namespace, серийник один
модем 102: 1 namespace, серийник один
каждый real даёт свой серийник — адреса не перепутаны
```

Опознание по `SerialNumber` из `/api/device/information`: это доказывает, что
за виртуальным адресом стоит именно назначенный модем, а не «что-нибудь, что
ответило». Веб-интерфейс открывается браузером по `http://192.168.64.1/`, и на
странице DHCP видно `192.168.101.1`.

Отдельно проверено, что посредники не копятся: `up` → 2 процесса,
два `restart` подряд → по-прежнему 2, `down` → 0.

Раньше, до развязки, проверялось и на 16 namespace — по 8 на каждый модем,
то есть с намеренным пересечением. Все 16 отдавали корректный серийник.

## Ограничения

`sing-box` 26 МБ + посредник 21 МБ = **~47 МБ на namespace**.

| | нужно RAM |
|---|---|
| 64 namespace | ~3.6 ГБ |
| 253 namespace (потолок) | ~12.5 ГБ |

Виртуальный номер живёт в `192.168.<n>.0/24`, поэтому больше 253 не бывает в
принципе — ещё минус те октеты, что заняты сетью самой ВМ (`ns_conflict()`
такие ловит до создания). Если упрётесь в память, первым делом стоит переписать
посредник с Python на компилируемое: он один съедает почти половину бюджета.

## Сборка из апстрима

```bash
python3 build.py --fetch
```

Скачает актуальный `proxyveth.py` из ProxyControlService и применит 25 правок.
Каждая ищется как точная подстрока и обязана встретиться ровно один раз — если
апстрим сдвинулся, сборка падает и называет отвалившуюся правку, а не выдаёт
молча полурабочий файл.

```bash
python3 build.py upstream-v3.3.py --check
```

`upstream-v3.3.py` — зафиксированная копия апстрима, на которой всё собиралось
и проверялось.

## Проверка сборки

```bash
python3 selftest.py proxyveth.py
```

Разбор таблицы, формы записи `real`, обход системных таблиц маршрутизации,
правка заголовков посредником. Ничего не меняет в системе, root не нужен,
работает на Linux (модуль тянет `fcntl`).
