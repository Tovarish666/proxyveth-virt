# ProxyVeth v3.4

Конвертация SOCKS5 прокси в виртуальные сетевые интерфейсы для [mobileproxy.space](https://mobileproxy.space).

Развитие [ProxyControlService](https://github.com/Tovarish666/ProxyControlService) v3.3:
номер, под которым модем видит mp.space, больше не обязан совпадать с номером
модема на его мини-сервере.

---

## Зачем

mp.space строит адрес управления жёстко: увидел модем на `192.168.N.100` —
пошёл на `192.168.N.1`. Значит `N` обязан быть уникальным в пределах ВМ.

Но `N` — это номер модема на **своём** мини-сервере, и при сведении нескольких
серверов в одну ВМ номера пересекаются: 1–10 на одном, 1–10 на другом,
101–115 на третьем. Раньше свести их было нельзя.

Теперь одно число разделено на два:

| | что это | уникальность |
|---|---|---|
| `n` | номер, под которым модем видит mp.space | обязана быть на ВМ |
| `real` | октет модема на его мини-сервере | только на своём сервере |

Модем физически на `192.168.101.1`, mp.space видит его как `192.168.64.100` и
стучится на `192.168.64.1` — и получает ответ именно этого модема.

---

## Как это работает

```
Мини-серверы (модемы + 3proxy → SOCKS5 gen1)
        │
        ▼
  Ubuntu VM (Proxmox)
  ├── ProxyVeth
  │     Для каждой строки таблицы (n=64, real=101):
  │     ┌─ network namespace ns_64 ─────────────────────────┐
  │     │  sing-box → SOCKS5 → реальный модем               │
  │     │  192.168.64.1 ← посредник → 192.168.101.1 (API)   │
  │     └───────────────────────────────────────────────────┘
  │           ↕ veth
  │     mdm64 = 192.168.64.100/24   (source routing, table 1064)
  │
  └── mobileproxy.space
        видит: 192.168.64.100 = модем 64
        API:   http://192.168.64.1 — работает ✓
```

**IP-схема для строки `n=64, real=101`:**

| Адрес | Роль |
|---|---|
| `192.168.64.100` | хост — mp.space видит как IP модема |
| `192.168.64.254` | namespace — шлюз для хоста |
| `192.168.64.1` | адрес управления, который знает mp.space |
| `192.168.101.1` | настоящая веб-морда Huawei, за прокси |
| `10.0.64.1/30` | tun внутри namespace |

## Быстрый деплой

```bash
wget -O /usr/local/bin/proxyveth.py https://raw.githubusercontent.com/Tovarish666/proxyveth-virt/main/proxyveth.py
```

```bash
chmod +x /usr/local/bin/proxyveth.py && ln -sf /usr/local/bin/proxyveth.py /usr/local/bin/proxyveth
```

```bash
mkdir -p /etc/proxyveth && echo 'SHEET_CSV_URL=https://docs.google.com/...' > /etc/proxyveth/env
```

```bash
proxyveth setup
```

`setup` сам поставит зависимости и sing-box, синхронизирует таблицу, поднимет
namespace и включит systemd-юниты.

**Настраивать больше нечего.** Единственное, что меняется от установки к
установке, — ссылка на таблицу. Всё остальное зашито в умолчания.

## Формат таблицы

Опубликовать как CSV (Файл → Опубликовать → CSV).

| n | real | proxy |
|---|---|---|
| 64 | 101 | `192.168.1.254:15000:modem101:te5xg83ted` |
| 246 | 102 | `192.168.1.254:15002:modem102:v4yeyzh43n` |

- **`n`** — номер для mp.space. Определяет `192.168.n.100` и `192.168.n.1`.
  Это колонка, а не позиция строки: вставка в середину не должна сдвигать
  раскладку.
- **`real`** — октет модема на его мини-сервере. Принимает `101`,
  `192.168.101.100` и `192.168.101.1` — берётся третий октет, чтобы колонку
  можно было заполнять копипастой откуда угодно.
  Синонимы названия: `modem`, `modem_n`, `modem_ip`, `mgmt`, `real_n`.
- **`proxy`** — `host:port:login:password`.

**Колонки `real` нет → `real = n` → поведение v3.3.** Старые таблицы работают
без единого изменения и без единого лишнего правила в системе.

Раздельные колонки тоже понимаются:

| n | real | proxy_host | proxy_port | login | password |
|---|---|---|---|---|---|

Колонка `enabled` (0/1) — отключить строку, не удаляя.

## Команды

```bash
proxyveth status              # статус всех namespace
proxyveth status --wan        # + проверка WAN IP (медленно)
proxyveth check N             # полная диагностика одного модема
proxyveth problems            # только проблемные
proxyveth up N | all          # поднять
proxyveth down N | all        # остановить
proxyveth restart N | all     # пересобрать
proxyveth sync                # обновить конфиг из таблицы
proxyveth autosync            # sync + применить разницу
proxyveth show-config         # текущий конфиг
proxyveth doctor              # проверка окружения
proxyveth cleanup             # снять всё своё
proxyveth rescue              # cleanup + отключить автозапуск
```

## Systemd

| Сервис | Роль |
|---|---|
| `proxyveth` | запуск всех NS при загрузке |
| `proxyveth-watchdog` | мониторинг каждые 60с, рестарт упавших |
| `proxyveth-autosync.timer` | синхронизация таблицы каждые 5 мин |

Смена `real` в таблице подхватывается автосинком и пересобирает namespace.

## Что изменилось против v3.3

**Колонка `real`** — развязка номеров, ради которой всё затевалось.

**Посредник Host.** Одного NAT не хватило: прошивка E3372 сверяет заголовок
`Host` и на чужой отвечает `307 Temporary Redirect`, не отдавая сессию.
Замерено на живом модеме — один пакет, одна разница:

| запрос | Host | ответ |
|---|---|---|
| `192.168.64.1` | `192.168.64.1` | **307** |
| `192.168.64.1` | `192.168.101.1` | **200 OK** |

Переписать заголовок на уровне пакетов нельзя — это содержимое потока. Поэтому
виртуальный адрес занимает посредник внутри namespace: правит `Host` в запросе
и адрес в `Location` ответа (на `GET /` модем отвечает
`Location: http://192.168.101.1/...` и увёл бы браузер на реальный адрес).
Запускается сам, снимается сам, виден в `check` и `status`. Отдельных демонов
и скриптов нет.

**`VETH_PREFIX` по умолчанию `mdm`, а не `eth`.** mp.space считает интерфейсы
`eth*` своими и сбрасывает на них IPv4, если такого модема нет в его конфиге.
Адрес исчезает, следом ядро выбрасывает default из таблицы, и sing-box пишет
`no route to host` на адрес SOCKS5. Снаружи выглядит как «модем то отвечает,
то нет».

**`RT_TABLE_BASE` по умолчанию `1000`, а не `100`.** При базе 100 модемы
153/154/155 попадают в таблицы 253/254/255 — `default`, `main`, `local`, — и
`ns_down` выполняет `ip route flush table main`, снося маршрутизацию хоста
вместе с SSH. Пока `N_MAX` был 200, это ждало своего часа. Дополнительно
`rt_table()` уводит такие номера в сторону, даже если базу вернут на 100.

**`N_MAX` 200 → 254** — весь диапазон третьего октета.

## Проверено

ВМ `Msk1-2` (Ubuntu 24.04.4), два живых модема за прокси:

```
virt  real  SerialNumber           выход в сеть
64    101   9GVDW17215000571       178.176.72.38     ✓
246   102   9GVDW17516001299       128.71.101.119    ✓

каждый real даёт свой серийник — адреса не перепутаны
```

Опознание по `SerialNumber` из `/api/device/information`: доказывает, что за
виртуальным адресом стоит именно назначенный модем, а не «что-нибудь, что
ответило». Веб-интерфейс открывается браузером по `http://192.168.64.1/`, и на
странице DHCP видно `192.168.101.1`.

Отдельно проверялось на 16 namespace с намеренным пересечением — по 8 на
каждый модем; все 16 отдавали корректный серийник.

## Важные нюансы

**Сколько модемов влезет.** `sing-box` 26 МБ + посредник 21 МБ ≈ **47 МБ на
namespace**. На 64 модема нужно ~3.6 ГБ RAM. Потолок по адресам — 253: номер
живёт в `192.168.n.0/24`, и ещё минус октеты, занятые сетью самой ВМ
(`ns_conflict()` такие ловит до создания, а не после потери связи).

**Тело ответов NAT не переписывает.** `/api/dhcp/settings` вернёт настоящий
`192.168.101.1`. Для API по относительным путям безразлично; посредник правит
только `Location`.

**Переход со старой установки.** Интерфейсы переименовались с `ethN` на `mdmN`,
поэтому старые хвосты новая версия не увидит. Снимите всё **старой** версией
(`proxyveth down all`), потом обновляйте.

## Разработка

Файл собирается из апстрима, а не форкнут намертво, — чтобы правки переносились
на новые версии:

```bash
cd dev && python3 build.py --fetch -o ../proxyveth.py
```

27 правок, каждая ищется точной подстрокой и обязана встретиться ровно один
раз. Апстрим сдвинулся — сборка падает и называет отвалившуюся правку, вместо
того чтобы молча выдать полурабочий файл.

```bash
cd dev && python3 selftest.py ../proxyveth.py
```

Разбор таблицы, формы записи `real`, обход системных таблиц маршрутизации,
правка заголовков посредником. Root не нужен, систему не трогает.
